# Инструкция

**Что делает программа.** Вы описываете процесс таблицей — она рисует схему:
картинку и файл, который открывается в редакторах схем. Умеет и обратно:
из готовой схемы сделать таблицу.

Обычный путь такой — таблицу за вас составит нейросеть:

```
Регламент.docx  →  Регламент.md  →  таблица.txt  →  папка «Договор»
   ваш файл        превратили       составила        картинка, схема
                  в простой текст     нейросеть       и таблица рядом
```

Нейросеть будет ошибаться — это нормально. Утилита сама скажет, что не так,
вы скопируете её слова обратно нейросети, и та исправит. Обычно хватает
одного-двух заходов.

# Часть 1. Установка. Делается один раз

Нужен Linux с терминалом и Python 3.10 или новее. Вводите команды по одной
и сверяйте ответ.

**1. Проверить Python**

```bash
python3 --version
```

Должно ответить `Python 3.10` или больше — 3.11, 3.12, 3.13 тоже подходят.

**2. Скачать проект**

```bash
cd ~
git clone https://github.com/Djytnek/xlsx2bpmn.git
```

**3. Установить**

```bash
python3 -m pip install --user "$HOME/xlsx2bpmn[docs]"
```

Последняя строка ответа должна быть `Successfully installed ... xlsx2bpmn-1.14.0`.

Добавка `[docs]` в конце приносит чтение Word и PDF — без неё работать
с регламентами не выйдет. **Ставится несколько минут, весит около 300 МБ.**

> Ответило `error: externally-managed-environment`? Значит **не установилось
> ничего**, ваш Linux так защищает системные пакеты. Повторите ту же команду
> с добавкой:
> `python3 -m pip install --user --break-system-packages "$HOME/xlsx2bpmn[docs]"`

**4. Проверить**

```bash
xlsx2bpmn --version
markitdown --help
```

Первая должна ответить номером версии, вторая — показать подсказку про
`markitdown <FILENAME>`. Ответили обе — установка удалась.

> Ответило `command not found`? Закройте терминал и откройте заново, потом
> повторите. Программа установлена, её просто ещё не видно в этом окне.

> **На сервере нет интернета?** Тогда эта часть не сработает — всё нужное
> уже лежит в проекте, порядок действий в части 6.

# Часть 2. Работа: из документа в схему

Дальше — живой пример: регламент согласования договора. Ваши файлы будут
называться иначе, всё остальное так же.

## Шаг 1. Превратить документ в простой текст

Нейросеть не читает `.docx` и `.pdf` напрямую. Превращаем в текст:

```bash
cd ~
markitdown Регламент.docx > Регламент.md
```

Рядом появится файл `Регламент.md`. Откройте его двойным щелчком — внутри
должен быть текст вашего регламента:

```
Регламент согласования договора

1. Менеджер готовит проект договора и передаёт его юристу.
2. Юрист проверяет договор. Если есть замечания, договор возвращается
   менеджеру на доработку.
3. Если замечаний нет, договор уходит на подпись директору.
4. Директор подписывает договор, после чего процесс завершён.
```

Так же работает с `.pdf`, `.pptx`, `.xlsx`, `.html` — меняется только имя
файла.

> **Вышло пусто?** Значит документ — скан, картинка внутри Word. Текста там
> нет, и взять его неоткуда: описание придётся набрать руками в обычном
> текстовом файле. Дальше всё то же самое.

## Шаг 2. Взять промпт

Промпт — готовое задание для нейросети, где расписано, какой должна быть
таблица: какие колонки, какие типы шагов, как разносить роли по дорожкам
и когда заводить подпроцессы. Он лежит в папке проекта:

```
xlsx2bpmn / xlsx2bpmn / prompt.md
```

Откройте его и скопируйте целиком. В первых строках есть два места в двойных
фигурных скобках — замените их на **полные пути к файлам**:

| Что заменить | На что |
|---|---|
| `{{INPUT_MD}}` | `/home/имя/Регламент.md` — файл из шага 1 |
| `{{OUTPUT_TXT}}` | `/home/имя/таблица.txt` — как назвать результат |

Путь нужен полный, от самого начала: нейросеть открывает файл сама, и просто
`Регламент.md` она может не найти.

## Шаг 3. Отдать промпт нейросети

Вставьте промпт с подставленными путями — и всё. Нейросеть сама откроет
`Регламент.md`, разберёт его и запишет `таблица.txt` рядом. Ни копировать
текст регламента, ни сохранять ответ руками не нужно.

Когда она закончит, откройте `таблица.txt` и посмотрите, что вышло.
Выглядеть должно так:

```
id|name|type|pool|lane|next|message_to|data_in|data_out
s|Нужен договор|startEvent|ООО «Ромашка»|Менеджер|t1|||
t1|Подготовить проект договора|userTask|ООО «Ромашка»|Менеджер|t2|||
t2|Проверить договор|userTask|ООО «Ромашка»|Юрист|g1|||
g1|Есть замечания?|exclusiveGateway|ООО «Ромашка»|Юрист|t1 [Да]; *t3 [Нет]|||
t3|Подписать договор|userTask|ООО «Ромашка»|Директор|e|||
e|Договор подписан|endEvent|ООО «Ромашка»|Директор||||
```

## Шаг 4. Отдать таблицу утилите

```bash
xlsx2bpmn таблица.txt --all-levels -o Договор
```

`--all-levels` — то, что нужно в работе: он складывает всё в одну папку,
и картинку, и схему, и таблицу. `-o Договор` — как назвать папку.

**Получилось** — утилита перечислит, что сложила:

```
Папка: Договор
  01-Договор.xlsx + .bpmn + .png   весь процесс, элементов 6
Готово: уровней 1, файлов 3
```

Откройте папку `Договор` — внутри три файла:

```
01-Договор.png     картинка — показать людям
01-Договор.bpmn    схема — открыть в редакторе и править мышкой
01-Договор.xlsx    таблица — та же схема словами, править в Excel
```

Щёлкните по `.png`. **Готово.**

> **Про уровни.** Уровень — это подпроцесс: шаг, внутри которого спрятана
> своя последовательность действий. Нейросеть заводит их сама, когда в вашем
> регламенте один шаг расписан через несколько других. Тогда у каждого
> подпроцесса будет своя тройка файлов:
>
> ```
> Папка: Закупка
>   01-Закупка.xlsx + .bpmn + .png                весь процесс, элементов 10
>   02-Проверка-поставщика.xlsx + .bpmn + .png    sub_check, элементов 5
> Готово: уровней 2, файлов 6
> ```
>
> Так и должно быть: на общей картинке «Проверка поставщика» — один
> прямоугольник, а рядом лежит отдельная картинка с тем, что внутри.
> Если в регламенте таких вложенных описаний нет, уровень будет один.

**Не получилось** — появятся строки со словом `ERROR` и итог внизу:

```
таблица.txt: [строка 6] ERROR next ссылается на несуществующий id 'end'
таблица.txt: [строка 6] WARN  у 't3' нет исходящих потоков
таблица.txt: [строка 7] WARN  у 'e' нет входящих потоков
таблица.txt: не сконвертировано — ошибок 1
```

Тогда шаг 5.

> `WARN` — это замечания, они не мешают. Схема не собирается только
> из-за `ERROR`.

## Шаг 5. Отдать ошибки обратно нейросети

Скопируйте **все строки с ошибками целиком** и напишите нейросети так:

```
Утилита не приняла таблицу и ответила:

таблица.txt: [строка 6] ERROR next ссылается на несуществующий id 'end'
таблица.txt: не сконвертировано — ошибок 1

Исправь таблицу и пришли её целиком.
```

Сообщения написаны понятным языком специально для этого: видно и номер
строки, и что именно не так. Нейросеть пришлёт исправленную таблицу —
замените ею содержимое `таблица.txt` и **вернитесь на шаг 4**.

Так по кругу, пока не появится `OK`. В примере выше нейросеть написала `end`
вместо `e` — после исправления одной буквы схема собралась.

# Часть 3. Если готового документа нет

Таблицу можно набрать и руками — она простая. Создайте текстовый файл
`Отпуск.txt` и вставьте в него:

```
id|name|type|pool|lane|next
s|Нужен отпуск|startEvent|ООО «Ромашка»|Сотрудник|t1
t1|Написать заявление|userTask|ООО «Ромашка»|Сотрудник|t2
t2|Согласовать|userTask|ООО «Ромашка»|Руководитель|t3
t3|Оформить приказ|userTask|ООО «Ромашка»|Кадры|e
e|Отпуск оформлен|endEvent|ООО «Ромашка»|Кадры|
```

Сохраните и выполните:

```bash
xlsx2bpmn Отпуск.txt -o Отпуск.png
```

Появится картинка с тремя дорожками: «Сотрудник», «Руководитель», «Кадры».

**Как читается таблица.** Каждая строка — один шаг, колонки разделены
чертой `|`:

| Колонка | Что писать |
|---|---|
| `id` | короткое имя строки латиницей: `s`, `t1`, `e`. Чтобы на неё ссылаться |
| `name` | название шага по-русски — оно попадёт на схему |
| `type` | что это за шаг, см. ниже |
| `pool` | название организации. Обычно у всех строк одно и то же |
| `lane` | роль или отдел. Для каждой роли будет своя полоса |
| `next` | `id` следующего шага. У последнего пусто |

Типов достаточно четырёх:

| `type` | Что означает | Как выглядит |
|---|---|---|
| `startEvent` | начало процесса | кружок |
| `userTask` | человек что-то делает | прямоугольник |
| `exclusiveGateway` | вопрос, развилка | ромб |
| `endEvent` | конец процесса | жирный кружок |

**Развилка.** У ромба в колонке `next` пишут несколько ответов через точку
с запятой, подпись ветки — в квадратных скобках:

```
g|Сумма больше 100 000?|exclusiveGateway|ООО «Ромашка»|Бухгалтер|t1 [Да]; *t2 [Нет]
```

Звёздочка `*` помечает ветку «во всех остальных случаях» — без неё программа
скажет, что не знает, куда идти.

**Готовый шаблон с примером** для Excel или LibreOffice:

```bash
xlsx2bpmn --template Процесс.xlsx
```

# Часть 4. Обратный ход: из схемы в описание

Бывает наоборот: схема есть — от коллеги, из другой системы, — а нужен текст,
который можно приложить к регламенту или отдать на согласование. Тоже два
шага.

**1. Превратить схему в таблицу.** Это делает утилита:

```bash
bpmn2xlsx Схема.bpmn --txt -o таблица.txt
```

**2. Превратить таблицу в текст.** Это делает нейросеть — для неё есть
отдельный промпт, рядом с первым:

```
xlsx2bpmn / xlsx2bpmn / prompt-back.md
```

Откройте, скопируйте, замените два места полными путями — как в шаге 2:

| Что заменить | На что |
|---|---|
| `{{INPUT_TXT}}` | `/home/имя/таблица.txt` — таблица из шага 1 |
| `{{OUTPUT_MD}}` | `/home/имя/описание.md` — куда записать текст |

Нейросеть прочитает таблицу и напишет описание: участники, ход процесса
по шагам, развилки с условиями, документы и отдельный раздел на каждый
подпроцесс. Служебные `id` в текст не попадут — останется готовый текст,
который можно приложить к регламенту.

# Часть 5. Что ещё умеет

```bash
xlsx2bpmn таблица.txt -o Схема.png   # только картинка, без папки
xlsx2bpmn таблица.txt                # только файл .bpmn для редактора
bpmn2xlsx Договор/01-Договор.bpmn    # обратно: из схемы в таблицу
xlsx2bpmn таблица.txt --levels       # показать, какие в схеме есть уровни
```

Файл `.bpmn` можно перетащить на сайт demo.bpmn.io или открыть в Camunda
Modeler и править схему мышкой.

Круг замкнут: таблица → схема → таблица возвращает ровно ту же таблицу,
ничего не теряя.

# Часть 6. Установка без интернета

Бывает, что на сервере сети нет вовсе. Тогда обычная установка не пройдёт:
она ходит в интернет за библиотеками. Всё нужное уже лежит в проекте,
в папке `offline`.

## Что перенести

На машине **с интернетом** скачайте проект (или возьмите готовую папку
`offline` из клона) и перенесите на сервер два файла:

```
offline/xlsx2bpmn-1.14.0-py3-none-any.whl   505 КБ — сама утилита
offline/markitdown-offline.zip               92 МБ — чтение Word и PDF
```

Второй нужен, только если сервер должен сам читать `.docx` и `.pdf`.
Если документы вы превращаете в текст на своей машине, а на сервер несёте
готовый `.md` — хватит первого файла.

Но если вы не уверены, что на сервере есть `openpyxl` и `pillow`, берите оба:
эти две библиотеки тоже лежат внутри архива.

Переносите любым способом: `scp`, панель управления, флешка.

## Шаг 1. Поставить утилиту

Сначала проверьте, что нужные библиотеки на сервере уже есть:

```bash
python3 -c "import openpyxl, PIL; print('библиотеки на месте')"
```

Ответило `библиотеки на месте` — ставьте:

```bash
python3 -m pip install --no-index --no-deps xlsx2bpmn-1.14.0-py3-none-any.whl
```

> **Ответило ошибкой?** Значит библиотек нет. Они лежат в том же архиве —
> распакуйте его и поставьте оттуда, а потом вернитесь к команде выше:
>
> ```bash
> unzip -o markitdown-offline.zip
> python3 -m pip install --no-index --find-links markitdown-wheels openpyxl pillow
> ```

`--no-index` запрещает pip выходить в сеть, `--no-deps` — не проверять
зависимости, они уже есть. Оба ключа обязательны.

## Шаг 2. Разрешить запуск по имени

На серверах и в контейнерах папка `~/.local/bin`, куда попадают команды,
часто не входит в список тех, где терминал их ищет. Pip об этом
предупреждает строкой `installed in '...' which is not on PATH`.

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && export PATH="$HOME/.local/bin:$PATH"
```

Строка делает две вещи: чинит навсегда и включает прямо сейчас, без
перезахода. Проверьте:

```bash
xlsx2bpmn --version
```

Должно ответить `xlsx2bpmn 1.14.0`.

## Шаг 3. Поставить markitdown

Только если сервер должен сам читать Word и PDF.

```bash
unzip -o markitdown-offline.zip
python3 -m pip install --no-index --find-links markitdown-wheels "markitdown[docx,pdf,pptx,xlsx]==0.1.7"
markitdown --help
```

Версия `==0.1.7` указана не для красоты: без неё pip выберет старую `0.0.2`,
которая утилите не подходит.

## Что может пойти не так

| На экране | Что случилось | Что делать |
|---|---|---|
| `Cannot import 'setuptools.build_meta'` | вы ставите **из папки** с исходниками, а на сервере нечем собирать | ставьте из готового файла `.whl`, как в шаге 1 |
| `No matching distribution found for magika` | ставите markitdown без зависимостей | нужен весь `markitdown-offline.zip`, одного файла markitdown мало |
| `command not found` после успешной установки | папка `~/.local/bin` не в PATH | шаг 2 |
| `error: externally-managed-environment` | система запретила установку, не поставилось ничего | добавьте `--break-system-packages` к команде установки |
| `Defaulting to user installation because normal site-packages is not writeable` | это **не ошибка**, а сообщение: ставится в вашу личную папку | ничего, продолжайте |
| `ERROR: ... is not a supported wheel on this platform` | колёса markitdown собраны под другую версию Python | пересоберите архив, команда в `offline/README.md` |

## Чего офлайн не будет

**Раскладчик схем работает**, он лежит внутри пакета — при условии, что
на сервере есть Node.js (`node --version`). Если его нет, схемы всё равно
соберутся, просто встроенным раскладчиком: линии он ведёт хуже.

**Нейросеть** — по вашей обстановке. Утилита сама по себе к ней
не обращается: она принимает готовую таблицу.

# Часть 7. Если не получилось

| На экране | Что делать |
|---|---|
| `command not found` | закрыть терминал и открыть заново. Если не помогло — раздел 1 в [README.md](README.md) |
| `error: externally-managed-environment` | повторить установку с `--break-system-packages` |
| `markitdown: command not found` | установлено без `[docs]`. Повторите установку с этой добавкой |
| `В текстовом файле не найден разделитель '\|'` | нейросеть отдала таблицу в другом виде. Попросите: «колонки разделяй вертикальной чертой, без markdown-разметки» |
| `в пуле 'X' нет startEvent` | нет строки начала процесса. Отдайте ошибку нейросети |
| `next ссылается на несуществующий id` | опечатка: указан шаг, которого в таблице нет |
| `не сконвертировано — ошибок N` | это итог, сами ошибки в строках выше. Копируйте их все |
| `это не BPMN-диаграмма` | таблицу подали команде `bpmn2xlsx`. Таблицу в схему превращает `xlsx2bpmn` |
| `No such file or directory` | опечатка в имени файла или вы не в той папке. `ls` покажет, что рядом |
| в файле строки вроде «Вот таблица:» | уберите всё, кроме самой таблицы: в нём должна быть только она |
| нейросеть не открывает файлы, а показывает ответ в чате | вставьте ей текст регламента следом за промптом, а таблицу из ответа сохраните сами в текстовый файл `таблица.txt` |

Испортить ничего нельзя: утилита только читает вашу таблицу и создаёт новые
файлы рядом.

Всё остальное — в [README.md](README.md): документы на схеме, подпроцессы,
несколько организаций, обновление программы.
