# Установка «BPMN-схема» в Open WebUI

Инструкция для администратора сервера. Делать по порядку сверху вниз,
ничего не пропуская. Занимает около 20 минут.

**Что получится.** В списке моделей Open WebUI появится «BPMN-схема».
Сотрудник выбирает её, вставляет описание процесса обычным текстом и получает
готовую BPMN-схему картинкой, файл `.bpmn` для редактора и возможность править
схему словами прямо в переписке.

**Что нужно иметь.** Open WebUI в Docker, доступ администратора к нему,
доступ по SSH к серверу и установленная модель `qwen3.6:27b-110k`.

---

## Шаг 1. Скачать проект на сервер

Подключитесь к серверу по SSH и выполните:

```bash
cd /opt
git clone https://github.com/Djytnek/xlsx2bpmn.git
```

Git спросит логин и токен GitHub — репозиторий приватный.

---

## Шаг 2. Установить пакет внутрь Open WebUI

Узнайте имя контейнера:

```bash
docker ps --format "{{.Names}}" | grep -i open-webui
```

Дальше в инструкции контейнер называется `open-webui`. Если у вас имя другое,
подставляйте своё во все команды ниже.

Скопируйте проект в контейнер и установите:

```bash
docker cp /opt/xlsx2bpmn open-webui:/tmp/xlsx2bpmn
docker exec open-webui pip install /tmp/xlsx2bpmn
```

Проверьте:

```bash
docker exec open-webui python -c "import xlsx2bpmn; print(xlsx2bpmn.__version__)"
```

Должно напечатать `1.1.0`.

Проверьте, что мотор исправен:

```bash
docker exec open-webui python /tmp/xlsx2bpmn/selftest.py
```

Последняя строка должна быть `ВСЁ ХОРОШО`.

> После пересоздания контейнера Open WebUI обе команды установки нужно
> выполнить заново. Добавьте их в свой скрипт запуска контейнера.

---

## Шаг 3. Создать ключ доступа

1. Откройте Open WebUI в браузере.
2. Нажмите на своё имя слева внизу → **Настройки**.
3. Раздел **Аккаунт** → блок **Ключи API**.
4. Нажмите **Показать**, затем **Создать новый ключ**.
5. Скопируйте ключ целиком, он начинается на `sk-`.

Сохраните его в блокноте — понадобится на шаге 6.

---

## Шаг 4. Создать модель-исполнитель

Это модель, которая будет составлять таблицу процесса. Отдельная запись нужна
ради размера контекста: по умолчанию Ollama даёт короткую память, модель не
дочитывает инструкцию, и схемы получаются обрезанными.

Откройте **Рабочее пространство** → **Модели** → **+ Добавить модель**.
Заполняйте сверху вниз.

### Верх страницы

**Название модели** — впишите:

```
bpmn-worker
```

**Базовая модель (от)** — раскройте список и выберите:

```
qwen3.6:27b-110k
```

**Описание** — впишите:

```
Служебная. Составляет таблицу процесса для функции BPMN-схема.
```

**Добавить тег** — пропустите, оставьте пустым.

**Системный промпт** — **оставьте пустым**. Всю инструкцию функция передаёт
модели сама при каждом обращении. Если вписать сюда что-то своё, оно будет
добавляться к инструкции и мешать.

### Расширенные параметры

Нажмите **Расширенные параметры** — раскроется список полей, у всех написано
«По умолчанию». Поменяйте ровно четыре, остальные не трогайте.

| Поле | Поставьте | Зачем |
|---|---|---|
| **num_ctx (Ollama)** | `16384` | Память модели. Главное поле: при меньшем значении длинные процессы обрываются на середине |
| **Температура** | `0` | Модель перестаёт выдумывать, одинаковый ввод даёт одинаковый результат |
| **think (Ollama)** | выключить | Модель не должна рассуждать вслух, от неё нужна только таблица |
| **Потоковый вывод ответа** | выключить | Функция читает ответ целиком, по кусочкам он ей не нужен |

Все прочие поля — `top_p`, `top_k`, `max_tokens`, `repeat_penalty`,
`mirostat`, `num_gpu`, `keep_alive` и остальные — оставьте «По умолчанию».

### Низ страницы

Здесь идут разделы **Промпты**, **Знания**, **Инструменты**, **Скиллы**,
**Действия** и блок **Возможности** с галочками.

**Не трогайте ни один из них.** Эта модель только пишет текст: ни знания, ни
инструменты, ни веб-поиск, ни интерпретатор кода ей не нужны. Галочки в блоке
«Возможности» оставьте в том виде, в каком они стоят по умолчанию — функция
их не использует.

Поля **Терминал** и **Голос TTS** тоже пропустите.

Нажмите **Сохранить и создать** внизу страницы.

### Спрятать модель от сотрудников

Модель служебная, сотрудникам в списке она не нужна. В **Рабочее пространство**
→ **Модели** найдите строку `bpmn-worker` и **выключите переключатель справа**.
Функция обращается к ней по имени, видимость на это не влияет.

---

## Шаг 5. Добавить функцию

1. Откройте **Панель администратора** → вкладка **Функции**.
2. Нажмите **+** справа сверху.
3. Откройте на сервере файл `/opt/xlsx2bpmn/owui/bpmn_pipe.py`, выделите всё
   содержимое, скопируйте.
4. Вставьте в большое поле кода в Open WebUI, полностью заменив то, что там
   было.
5. Поле «Название» заполнится само — `BPMN-схема`.
6. Нажмите **Сохранить**.
7. В списке функций найдите `BPMN-схема` и **включите переключатель справа**.
   Без этого функция не появится в списке моделей.

---

## Шаг 6. Настроить функцию

**Панель администратора** → **Функции** → шестерёнка рядом с `BPMN-схема`
→ **Настроить**.

| Настройка | Значение |
|---|---|
| **MODEL** | `bpmn-worker` |
| **BASE_URL** | `http://localhost:8080` |
| **API_PATH** | `/api/chat/completions` |
| **API_KEY** | ключ `sk-...` из шага 3 |
| **REPAIRS** | `2` |
| **TIMEOUT** | `600` |
| **OUTPUT_DIR** | `/app/backend/data/bpmn` |
| **SHOW_TABLE** | выключено |

Нажмите **Сохранить**.

---

## Шаг 7. Проверить

1. Откройте новый чат.
2. В списке моделей сверху выберите **BPMN-схема**.
3. Вставьте текст и отправьте:

```
Заявка на отпуск поступает в отдел кадров. Кадровик проверяет остаток дней.
Если дней хватает, руководитель согласует заявление, после чего кадровик
вносит приказ. Если не хватает, сотруднику отправляют отказ.
```

Сверху побегут строчки «Читаю описание процесса…», «Рисую схему…», «Готово».
Затем появится картинка схемы с рамкой компании и дорожками ролей, под ней —
перечень шагов, ещё ниже — имена сохранённых файлов.

4. Напишите следующим сообщением:

```
добавь после согласования уведомление сотруднику
```

Схема должна перерисоваться с новым шагом.

Получилось — установка закончена.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| В списке моделей нет «BPMN-схема» | Не включён переключатель функции: шаг 5, пункт 7 |
| «Не найден файл prompt.md внутри пакета» | Пакет встал не полностью, повторите шаг 2 |
| «Не получилось обратиться к модели» | Неверные MODEL, BASE_URL или API_KEY: шаг 6 |
| Ошибка 401 или 403 | Ключ API недействителен, сделайте новый: шаг 3 |
| Схема обрывается на середине | Мал `num_ctx`, поставьте 16384: шаг 4 |
| Схема собирается по минуте и дольше | Модель тяжела для этого сервера. В шаге 4 смените базовую модель на `gemma4:26b` и сохраните |
| «Не получилось собрать схему» | Это не поломка: описание процесса неоднозначно. Сотруднику нужно дописать, что идёт после каждого шага и чем процесс заканчивается |
| Картинка не показана, текст и файлы есть | Версия Open WebUI не отображает встроенные картинки. Файлы `.svg` лежат в `OUTPUT_DIR` |
| После обновления Open WebUI всё пропало | Повторите шаг 2 |
| Open WebUI запущен без Docker | Уберите `docker exec` и `docker cp` из шага 2, ставьте пакет тем же `pip`, каким запущен Open WebUI, и перезапустите его |

## Где лежат готовые файлы

Внутри контейнера в `/app/backend/data/bpmn`. Забрать наружу:

```bash
docker cp open-webui:/app/backend/data/bpmn /opt/готовые-схемы
```

Чтобы сотрудники забирали файлы сами, примонтируйте эту папку на сетевой диск
при запуске контейнера.
