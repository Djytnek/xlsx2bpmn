# Установка «BPMN-схема» в Open WebUI

Пошагово. Делать по порядку, ничего не пропуская. Все команды выполняются
на сервере, где стоит Open WebUI.

**Что получится в итоге:** в списке моделей Open WebUI появится «BPMN-схема».
Сотрудник выбирает её, вставляет описание процесса обычным текстом и получает
готовую BPMN-схему картинкой, файл `.bpmn` для редактора и возможность править
схему словами прямо в переписке.

---

## Часть 1. Что нужно проверить перед началом

1. Open WebUI работает и вы заходите в него **администратором**
   (в меню слева внизу есть пункт «Панель администратора»).
2. Есть хотя бы одна рабочая локальная модель — та, что будет составлять
   таблицу. Рекомендуется `qwen3.6:35b`, при нехватке памяти `qwen3.6:27b-110k`.
3. Вы знаете, как Open WebUI запущен: в Docker или напрямую. От этого зависит
   только шаг 2.4.

Проверьте модель: откройте обычный чат, выберите её, напишите «привет».
Ответила — годится.

---

## Часть 2. Установка пакета `xlsx2bpmn`

Пакет — это «мотор»: он собирает схему из таблицы и рисует картинку.
Его нужно положить внутрь Open WebUI.

### 2.1. Получить проект на сервер

Репозиторий приватный, поэтому нужен доступ. Любой из двух способов:

**Через git** — если на сервере есть git и ваш аккаунт добавлен в репозиторий:

```bash
cd /opt
git clone https://github.com/Djytnek/xlsx2bpmn.git
```

**Через браузер** — если git на сервере нет. На странице репозитория зелёная
кнопка **Code** → **Download ZIP**, затем перенесите архив на сервер и
распакуйте:

```bash
unzip xlsx2bpmn-main.zip -d /opt
mv /opt/xlsx2bpmn-main /opt/xlsx2bpmn
```

Дальше в инструкции путь `/opt/xlsx2bpmn` — если положили в другое место,
подставляйте своё.

### 2.2. Определить, где живёт Open WebUI

```bash
docker ps | grep -i open-webui
```

- **Строка нашлась** → Open WebUI в Docker. Запомните имя контейнера из
  последнего столбца (обычно `open-webui`). Идите в 2.3.
- **Ничего не нашлось** → Open WebUI запущен напрямую. Идите в 2.4.

### 2.3. Установка в Docker

Скопируйте проект внутрь контейнера:

```bash
docker cp /opt/xlsx2bpmn open-webui:/tmp/xlsx2bpmn
```

Проверьте, есть ли уже нужная зависимость — чаще всего она в контейнере есть:

```bash
docker exec open-webui pip show openpyxl
```

**Если вывелись сведения о пакете** — ставьте без интернета вообще:

```bash
docker exec open-webui pip install --no-deps /tmp/xlsx2bpmn
```

**Если написало `WARNING: Package(s) not found`** — тогда так:

```bash
docker exec open-webui pip install /tmp/xlsx2bpmn
```

Этой команде нужен интернет: она докачает `openpyxl`. Если сервер без сети,
смотрите 2.5.

Проверьте, что встало:

```bash
docker exec open-webui python -c "import xlsx2bpmn; print(xlsx2bpmn.__version__)"
```

Должно напечатать номер версии. Напечаталось — идите в часть 3.

> **Важно.** После обновления или пересоздания контейнера Open WebUI пакет
> придётся поставить заново — команды те же. Чтобы этого избежать, добавьте
> их в свой скрипт запуска контейнера.

### 2.4. Установка без Docker

Определите, каким Python запущен Open WebUI, и поставьте пакет тем же самым:

```bash
/путь/к/окружению/bin/pip install /opt/xlsx2bpmn
/путь/к/окружению/bin/python -c "import xlsx2bpmn; print(xlsx2bpmn.__version__)"
```

После установки **перезапустите Open WebUI**.

### 2.5. Если на сервере нет интернета

На любой машине с сетью скачайте зависимости и перенесите их на сервер:

```bash
pip download openpyxl et-xmlfile -d колёса
docker cp колёса open-webui:/tmp/колёса
docker exec open-webui pip install --no-index --find-links /tmp/колёса openpyxl
docker exec open-webui pip install --no-deps /tmp/xlsx2bpmn
```

## Часть 3. Добавление функции

Функция — это «пульт»: она принимает описание от сотрудника, поручает модели
составить таблицу, проверяет её, при ошибках просит модель исправиться,
и рисует итоговую схему.

1. Откройте **Панель администратора** → вкладка **Функции**.
2. Нажмите **+** справа сверху.
3. Возьмите содержимое файла `owui/bpmn_pipe.py` из проекта. Его можно
   открыть в блокноте на сервере или прямо на странице репозитория на GitHub
   (кнопка копирования в правом верхнем углу файла).
4. Вставьте в большое поле кода в Open WebUI, заменив всё, что там было.
5. Поле «Название» заполнится само — `BPMN-схема`. Если нет, впишите вручную.
6. Нажмите **Сохранить**.
7. В списке функций найдите строку `BPMN-схема` и **включите переключатель**
   справа. Без этого функция не заработает.

Если после сохранения появилась красная надпись про `xlsx2bpmn` — значит
часть 2 не удалась. Вернитесь к ней.

---

## Часть 4. Ключ доступа к API

Функция обращается к модели через сам Open WebUI, поэтому ей нужен ключ.

1. Нажмите на своё имя слева внизу → **Настройки**.
2. Раздел **Аккаунт** → блок **Ключи API**.
3. Нажмите **Показать** рядом с «Ключ API», затем **Создать новый ключ**.
4. Скопируйте ключ целиком. Он начинается на `sk-`.
5. Сохраните его в блокноте — он понадобится в части 6.

> Если раздела «Ключи API» нет, включите его: Панель администратора →
> **Настройки** → **Основные** → «Ключи API» → включить.

---

## Часть 5. Модель-исполнитель

Это та модель, которая будет писать таблицу. Отдельная запись нужна ради
одной настройки — **размера контекста**. По умолчанию Ollama даёт модели
короткую память, и она не дочитает инструкцию до конца: схемы будут
получаться обрезанными.

Открывайте **Рабочее пространство** → **Модели** → **+ Добавить модель**.

### Поля сверху

| Поле | Что вписать |
|---|---|
| **Название модели** | `bpmn-worker` |
| **Базовая модель (от)** | выберите из списка `qwen3.6:35b` (или `qwen3.6:27b-110k`, если 35b тяжела) |
| **Описание** | `Составляет таблицу процесса. Напрямую не использовать.` |
| **Добавить тег** | оставьте пустым |
| **Системный промпт** | **оставьте пустым.** Инструкцию функция передаёт сама |

### Расширенные параметры

Нажмите **Расширенные параметры**, чтобы раскрыть список. Найдите в нём
следующие поля и поменяйте только их — все остальные оставьте
на значении «По умолчанию».

| Параметр | Значение | Зачем |
|---|---|---|
| **num_ctx (Ollama)** | `16384` | **Самое важное поле.** Память модели. Меньше 8192 ставить нельзя |
| **Температура** | `0` | Убирает выдумывание: одинаковый ввод даёт одинаковый результат |
| **think (Ollama)** | выключить | Модель не должна рассуждать вслух, от неё нужна только таблица |
| **Потоковый вывод ответа** | выключить | Функция ждёт ответ целиком |

> Если поля `num_ctx` нет — значит модель поднята не через Ollama.
> Тогда пропустите его, но учтите: при коротком контексте длинные процессы
> будут собираться хуже.

### Возможности и остальное

Ниже на этой же странице есть блок **Возможности** с галочками и разделы
«Знания», «Инструменты», «Скиллы», «Действия».

**Ничего из этого трогать не надо.** Ни знания, ни инструменты этой модели
не нужны: она только пишет текст. Галочки оставьте как есть.

Нажмите **Сохранить и создать** внизу страницы.

### Спрятать её от сотрудников

Эта модель — служебная, сотрудникам она ни к чему. В списке моделей найдите
`bpmn-worker` и **выключите переключатель видимости** справа. Функция будет
обращаться к ней по имени, а в списке выбора она не появится.

## Часть 6. Настройка функции

Возвращайтесь: **Панель администратора** → **Функции** → шестерёнка рядом
с `BPMN-схема` → **Настроить** (Valves).

| Настройка | Значение |
|---|---|
| **MODEL** | `bpmn-worker` — имя из части 5 |
| **BASE_URL** | `http://localhost:8080` |
| **API_PATH** | `/api/chat/completions` |
| **API_KEY** | ключ `sk-...` из части 4 |
| **REPAIRS** | `2` |
| **TIMEOUT** | `600` |
| **OUTPUT_DIR** | `/app/backend/data/bpmn` |
| **SHOW_TABLE** | выключено |

Нажмите **Сохранить**.

> **Про BASE_URL.** `http://localhost:8080` подходит, если функция и Open WebUI
> в одном контейнере — а это обычный случай. Если Open WebUI слушает другой
> порт, поставьте его. Проверить порт можно в адресной строке браузера.

## Часть 7. Проверка

1. Откройте новый чат.
2. В списке моделей сверху выберите **BPMN-схема**.
3. Вставьте текст:

```
Заявка на отпуск поступает в отдел кадров. Кадровик проверяет остаток дней.
Если дней хватает, руководитель согласует заявление, после чего кадровик
вносит приказ. Если не хватает, сотруднику отправляют отказ.
```

4. Отправьте.

**Что должно произойти.** Сверху побегут строчки «Читаю описание процесса…»,
«Рисую схему…», «Готово». Затем появится картинка схемы с рамкой компании
и дорожками ролей, под ней — перечень шагов, ещё ниже — имена сохранённых
файлов.

5. Проверьте правку словами: напишите следующим сообщением
   «добавь после согласования уведомление сотруднику». Схема должна
   перерисоваться с новым шагом.

Всё сошлось — установка закончена.

## Часть 8. Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| В списке моделей нет «BPMN-схема» | Функция не включена: часть 3, шаг 7 |
| «Не найден файл prompt.md внутри пакета» | Пакет встал не полностью, переустановите: часть 2 |
| «Не получилось обратиться к модели» | Неверные MODEL, BASE_URL или API_KEY: часть 6 |
| Ошибка 401 или 403 | Ключ API неверен или отозван: сделайте новый, часть 4 |
| Схема обрывается на середине | Мал `num_ctx`: часть 5, поставьте 16384 |
| «Не получилось собрать схему» | Это не поломка. Описание процесса неоднозначно — сотруднику надо дописать, что идёт после каждого шага |
| Картинка не отображается, всё остальное есть | Ваша версия Open WebUI не показывает встроенные картинки. Файлы `.svg` при этом сохраняются в `OUTPUT_DIR` |
| После обновления Open WebUI всё пропало | Поставьте пакет заново: часть 2 |

### Где лежат готовые файлы

В папке из настройки `OUTPUT_DIR`, по умолчанию `/app/backend/data/bpmn`
внутри контейнера. Забрать их наружу:

```bash
docker cp open-webui:/app/backend/data/bpmn /opt/готовые-схемы
```

Чтобы сотрудники забирали файлы сами, примонтируйте эту папку на сетевой
диск при запуске контейнера.

### Проверка мотора отдельно от Open WebUI

Если непонятно, где сломалось, проверьте пакет сам по себе:

```bash
docker exec open-webui python /tmp/xlsx2bpmn/selftest.py
```

Скрипт прогоняет полный круг на встроенном примере и заканчивается словами
`ВСЁ ХОРОШО`. Если да — мотор исправен, ищите причину в частях 3–6.
