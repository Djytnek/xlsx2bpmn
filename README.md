# xlsx2bpmn

Таблица процесса ⇄ BPMN 2.0 XML с расставленными координатами.

Работает офлайн: ни сервера, ни сети, ни Docker. Ядру нужен только
`openpyxl` и `pillow`. Сеть нужна один раз, при установке.

```
xlsx2bpmn process.xlsx  →  process.bpmn      собрать диаграмму
bpmn2xlsx process.bpmn  →  process.xlsx      разобрать её обратно
```

Это одна программа под двумя именами: направление берётся из того, как её
позвали. Круг замкнут — таблица переживает оборот без искажений, что и
проверяет `selftest.py`.

## Состав

| Файл | Назначение |
|---|---|
| `xlsx2bpmn/core.py` | сборка BPMN из таблицы. Чистая функция, без ввода-вывода |
| `xlsx2bpmn/to_table.py` | разбор BPMN обратно в таблицу |
| `xlsx2bpmn/layout.py` | резка по пулам, сшивка, рамки пулов, дорожки, документы |
| `xlsx2bpmn/layout_native.py` | раскладчик координат на чистом Python |
| `xlsx2bpmn/render_svg.py` | отрисовка схемы в SVG |
| `xlsx2bpmn/render_png.py` | то же растром, через Pillow |
| `xlsx2bpmn/cli.py` | консольная утилита, обе команды |
| `xlsx2bpmn/template.xlsx` | шаблон таблицы с заполненным примером |
| `xlsx2bpmn/read_doc.py` | чтение описания процесса из docx, pdf и прочего |
| `xlsx2bpmn/prompt.md` | промпт для генерации таблицы языковой моделью |
| `owui/` | функция для Open WebUI и инструкция по установке |
| `selftest.py` | проверка работоспособности |

## 1. Установка

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/Djytnek/xlsx2bpmn.git
cd xlsx2bpmn
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install .
```

Чтобы вдобавок читать описания процессов из docx, pdf, pptx и xlsx:

```bash
pip install ".[docs]"
```

Это дополнение тянет около 300 МБ зависимостей. Без него работает всё
остальное, включая обе картинки.

Проверка:

```bash
xlsx2bpmn --help
python selftest.py
```

`selftest.py` прогоняет встроенный шаблон целиком и должен закончиться словами
`ВСЁ ХОРОШО`. Если да — всё установлено правильно.

Для разработки ставьте с `-e`, тогда правки в коде подхватываются без
переустановки:

```bash
pip install -e .
```

### Установка без интернета на сервере

Скачайте колёса на машине с сетью:

```bash
pip download openpyxl et-xmlfile -d wheels
```

Перенесите папку `wheels` вместе с проектом и поставьте офлайн:

```bash
pip install --no-index --find-links wheels openpyxl
pip install --no-index --no-build-isolation .
```

Дополнение `[docs]` так перенести сложнее: у него больше тридцати
зависимостей. Если сеть на сервере есть — ставьте его обычным способом.

## 2. Использование

```bash
xlsx2bpmn --template my_process.xlsx      # получить пустой шаблон
# ... заполнить таблицу ...
xlsx2bpmn my_process.xlsx                 # рядом появится my_process.bpmn
```

Основные варианты:

```bash
xlsx2bpmn process.xlsx -o schema.bpmn        # своё имя выходного файла
xlsx2bpmn *.xlsx                             # пачкой, каждому свой .bpmn
xlsx2bpmn process.xlsx --sheet Лист1         # таблица на другом листе
xlsx2bpmn process.xlsx --target camunda8 --executable
xlsx2bpmn process.xlsx --strict              # предупреждения тоже блокируют
xlsx2bpmn process.xlsx --report errors.txt   # отчёт в файл
xlsx2bpmn process.xlsx -q                    # только результат
```

### Ключи

| Ключ | Что делает |
|---|---|
| `-o, --output` | имя выходного файла; только для одного входного |
| `--template PATH` | создать пустой шаблон и выйти |
| `--sheet` | имя листа, по умолчанию `Process` |
| `--target` | `plain` (по умолчанию) или `camunda8` |
| `--no-layout` | не расставлять координаты, только структура |
| `--strict` | предупреждения блокируют генерацию наравне с ошибками |
| `--executable` | пометить процесс исполняемым |
| `--report PATH` | записать ошибки и предупреждения в файл |
| `--svg` | нарисовать картинку .svg рядом с результатом |
| `--png` | то же растром .png |
| `--to-bpmn` / `--to-table` | направление, если имя команды не подходит |
| `--txt` | при разборе писать текст вместо .xlsx |
| `-q, --quiet` | без подробного вывода |

### Коды возврата

`0` — успех, `1` — ошибки в таблице, `2` — файл не прочитан,
`3` — сбой раскладки. Удобно для скриптов:

```bash
xlsx2bpmn process.xlsx -q || echo "не собралось"
```

## 3. Форматы входа

Утилита принимает два формата, различая их по содержимому файла, а не по
расширению:

- **xlsx** — таблица из шаблона (`--template`);
- **текст** — колонки разделены вертикальной чертой `|`, кодировка UTF-8
  или CP1251.

Другие разделители не принимаются. Пробелы вокруг черт срезаются. При лишней
или недостающей черте утилита называет номер строки.

```bash
xlsx2bpmn process.txt -o process.bpmn
```

## 4. Как заполнять таблицу

Одна строка — один элемент. Связи пишутся у источника в колонке `next`.

| Что нужно | Как записать |
|---|---|
| Простой переход | `next: t_check` |
| Развилка AND | `next: t_invoice; t_pack` |
| Ветка с условием | `next: t_pay [Да] {amount > 1000}` |
| Ветка по умолчанию | `next: *t_reject [Нет]` |
| Сообщение в другой пул | `message_to: c_pay` |
| Задача создаёт документ | `data_out: doc_req` |
| Задача читает документ | `data_in: doc_req` |
| Сам документ | отдельная строка, `type: dataObject` |

Обязательные колонки — `id`, `type`, `pool`. Дорожки создаются
автоматически по названию в колонке `lane`. Полное описание всех колонок —
на листе «Справка» внутри шаблона.

### Документы

Документ объявляется отдельной строкой с `type = dataObject` и живёт внутри
одного пула. Движение читается по цепочке: одна задача его создаёт (`data_out`),
следующая читает (`data_in`).

Ограничение самого BPMN: передать документ из пула в пул ассоциацией нельзя —
между пулами идёт поток сообщений, а документ объявляется в каждом пуле свой.
Валидатор это ловит.

## 5. Генерация таблицы языковой моделью

В `xlsx2bpmn/prompt.md` лежит промпт для локальных моделей: закрытый список
типов, явный формат, два проверенных примера, чеклист самопроверки. Подставьте
свои пути вместо `{{INPUT_MD}}` и `{{OUTPUT_TXT}}`, отдайте модели, полученную
таблицу скормите утилите.

Готовая обвязка для Open WebUI — в `owui/`: там модель вызывается сама, ответ
проверяется, при ошибках возвращается ей на исправление. Описание процесса
можно не набирать, а приложить файлом — docx, pdf, pptx, xlsx, html читаются
через `markitdown`. Установка — `owui/УСТАНОВКА.md`.

Чтение документов включается дополнением `[docs]` при установке (раздел 1)
и доступно как обычная функция:

```python
from xlsx2bpmn import read_document
text = read_document(open("регламент.docx", "rb").read(), "регламент.docx")
```

Валидатор ловит битые ссылки и структурные ошибки, но не заметит, если модель
неверно поняла смысл процесса — результат проверяйте.

## 6. Проверка результата

Полученный `.bpmn` откройте в любом BPMN-редакторе: перетащите на
demo.bpmn.io или откройте в Camunda Desktop Modeler. Оба работают локально.

## 7. Обратный ход: диаграмма → таблица

```bash
bpmn2xlsx process.bpmn                  # рядом появится process.xlsx
bpmn2xlsx process.bpmn --txt            # текстовая таблица вместо книги
bpmn2xlsx схема.bpmn -o таблица.txt     # формат берётся из расширения
xlsx2bpmn process.bpmn --to-table       # то же самое другим именем
```

В `.xlsx` пишутся все 15 колонок поверх вложенного шаблона — выпадающие
списки и лист «Справка» остаются на месте. В текстовом виде выводятся только
заполненные колонки.

### Что не переживает разбор

Таблица — проекция BPMN, и проекция с потерями. Всё потерянное утилита
называет вслух, молча не выбрасывает ничего:

| Что | Судьба |
|---|---|
| координаты | теряются, при обратной сборке раскладчик расставит заново |
| пулы-ящики (participant без процесса) | в таблице не представимы |
| текстовые аннотации, связи, группы | в модели таблицы их нет |
| расширения движков (`zeebe:`, `camunda:`) | не переносятся |
| типы вне списка (`transaction`, `complexGateway`) | пропускаются |

Ссылки на всё пропущенное вычищаются, поэтому полученная таблица всегда
собирается обратно. Символ `|` в названиях заменяется на `/`, служебные
скобки в подписях потоков — на круглые; про каждую замену приходит
предупреждение.

Главное следствие для работы: **ручная компоновка не переживает оборот.**
Разложили схему в Modeler, прогнали через таблицу — координаты будут
посчитаны заново.

## 8. Раскладка координат

По умолчанию работает встроенный раскладчик на Python: узлы разносятся по
колонкам согласно длиннейшему пути от старта, а по вертикали — по дорожкам,
каждой своя полоса. Ничего не требует, результат детерминированный — один и
тот же вход даёт побайтово одинаковый файл, удобно хранить схемы в git.

Картинку можно получить сразу: ключ `--svg` рисует схему рядом с результатом,
без браузера и без зависимостей. Ключ `--png` даёт растр для писем и презентаций. Растр рисуется
через Pillow, шрифт лежит внутри пакета — системных библиотек не нужно
никаких. Оба ключа можно указать вместе.

### Своя раскладка

`apply_layout` вторым аргументом принимает любую функцию `str -> str`:
на вход XML с одним процессом, на выход он же с добавленным `BPMNDiagram`.
Ваша тулза расстановки координат подключается одной строкой.

## 9. Использование как библиотеки

```python
from xlsx2bpmn import convert, apply_layout, layout_process

result = convert(open("process.xlsx", "rb").read(), target="plain")

if not result.ok:
    for issue in result.issues:
        print(issue)                    # [строка 14] ERROR ...
else:
    xml, warnings = apply_layout(result.xml, layout_process)
    open("process.bpmn", "w", encoding="utf-8").write(xml)
```

`convert(data: bytes, *, sheet=None, strict=False, executable=False,
target="plain") -> Result`

`Result` содержит `ok`, `xml`, `issues` (у каждого — `level`, `row`, `message`)
и `stats`. Функция ничего не читает с диска и не пишет: даёте байты,
получаете результат.

Обратный ход устроен зеркально:

```python
from xlsx2bpmn import to_table, to_workbook

result = to_table(open("process.bpmn", encoding="utf-8").read())

print(result.table)                     # текст с разделителем |
for issue in result.warnings:
    print(issue)                        # что не уложилось в таблицу
```

`to_table(xml: str | bytes, *, full=False) -> TableResult`

`TableResult` содержит `table` (готовый текст), `rows` и `columns` (те же
данные структурой), `issues` и `stats`. При `full=True` выводятся все 15
колонок, иначе только заполненные. `to_workbook(result, template_bytes)`
раскладывает строки по шаблону и возвращает байты `.xlsx`.

Обе функции чистые — ни диска, ни сети, — поэтому пакет одинаково удобно
звать из скрипта, из веб-обвязки или из функции Open WebUI.

## 10. Если не сконвертировалось

Ошибки блокируют результат, предупреждения — нет. У каждой указан номер строки
таблицы. Самые частые:

| Сообщение | Причина |
|---|---|
| `next ссылается на несуществующий id` | опечатка в идентификаторе |
| `условия заданы у N, поток по умолчанию не указан` | у эксклюзивного шлюза не хватает условия или `*` |
| `документ объявлен в другом пуле` | документ живёт внутри одного пула |
| `в пуле нет startEvent` | у каждого пула должны быть старт и конец |
| `поток пересекает пулы` | между пулами используется `message_to`, а не `next` |

## 11. Ограничения

Встроенный раскладчик не минимизирует пересечения стрелок: на процессах с
множеством обратных связей схема будет читаемой, но не оптимальной.

Субпроцессы рисуются свёрнутыми — вложенное содержимое координат не получает.

Режим `camunda8` подставляет `zeebe:taskDefinition` с типом джоба, выведенным
из `id` задачи — это заглушка, проверьте перед развёртыванием. Корреляцию
сообщений таблица не описывает, её дописывают в Modeler.
