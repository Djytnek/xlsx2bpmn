# xlsx2bpmn

**Текущая версия: 1.13.0** — сверяйте с выводом `xlsx2bpmn --version`,
чтобы понять, доехало ли обновление.

Таблица процесса ⇄ BPMN 2.0 XML с расставленными координатами.

Работает офлайн: ни сервера, ни сети, ни Docker. Ядру нужен только
`openpyxl` и `pillow`. Сеть нужна один раз, при установке.

```
xlsx2bpmn process.xlsx  →  process.bpmn      собрать диаграмму
bpmn2xlsx process.bpmn  →  process.xlsx      разобрать её обратно
```

Это одна программа под двумя именами: направление берётся из того, как её
позвали. Круг замкнут — таблица переживает оборот без искажений, что и
проверяет `selftest.py`.

## Состав

| Файл | Назначение |
|---|---|
| `xlsx2bpmn/core.py` | сборка BPMN из таблицы. Чистая функция, без ввода-вывода |
| `xlsx2bpmn/to_table.py` | разбор BPMN обратно в таблицу |
| `xlsx2bpmn/layout.py` | резка по пулам, сшивка, рамки пулов, дорожки, документы |
| `xlsx2bpmn/layout_native.py` | раскладчик координат на чистом Python |
| `xlsx2bpmn/route.py` | развод стрелок в обход фигур |
| `xlsx2bpmn/render_svg.py` | отрисовка схемы в SVG |
| `xlsx2bpmn/render_png.py` | то же растром, через Pillow |
| `xlsx2bpmn/cli.py` | консольная утилита, обе команды |
| `xlsx2bpmn/template.xlsx` | шаблон таблицы с заполненным примером |
| `xlsx2bpmn/read_doc.py` | чтение описания процесса из docx, pdf и прочего |
| `xlsx2bpmn/prompt.md` | промпт для генерации таблицы языковой моделью |
| `owui/` | функция для Open WebUI и инструкция по установке |
| `xlsx2bpmn/layout-node/` | раскладчик bpmn-auto-layout, зашит одним файлом |
| `selftest.py` | проверка работоспособности |

## 1. Установка и обновление

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/Djytnek/xlsx2bpmn.git
cd xlsx2bpmn
pip install .
```

Чтобы вдобавок читать описания процессов из docx, pdf, pptx и xlsx:

```bash
pip install ".[docs]"
```

Это дополнение тянет около 300 МБ зависимостей. Без него работает всё
остальное, включая обе картинки.

### Проверить, что установлено

```bash
xlsx2bpmn --version
python selftest.py
```

`selftest.py` прогоняет полный круг на встроенном примере и должен
закончиться словами `ВСЁ ХОРОШО`.

### Обновление

Новые возможности появляются регулярно, а `pip` сам за ними не следит —
обновлять нужно вручную. Проще всего скачать заново: команды не зависят
от того, в какой папке вы находитесь.

```bash
cd /tmp && rm -rf xlsx2bpmn && git clone https://github.com/Djytnek/xlsx2bpmn.git
pip install --force-reinstall "/tmp/xlsx2bpmn[docs]"
```

Без дополнения — `pip install --force-reinstall /tmp/xlsx2bpmn`.

Проверьте, что версия сменилась:

```bash
xlsx2bpmn --version
```

> **Ключ не сработал или его нет** — значит обновление не прошло и осталась
> старая версия. Смотрите на последнюю строку вывода `pip`: нужна
> `Successfully installed`.

Если вы работаете в самой папке проекта и правите код, обновляйтесь через
`git pull` — но выполнять его нужно **внутри** склонированной папки, иначе
git ответит `Stopping at filesystem boundary`:

```bash
cd /путь/куда/клонировали/xlsx2bpmn
git pull
pip install .
```

### Установка без интернета

Скачайте колёса на машине с сетью:

```bash
pip download openpyxl et-xmlfile pillow -d wheels
```

Перенесите папку `wheels` вместе с проектом и поставьте офлайн:

```bash
pip install --no-index --find-links wheels openpyxl pillow
pip install --no-index --no-build-isolation .
```

Дополнение `[docs]` так перенести сложнее: у него больше тридцати
зависимостей. Если сеть на сервере есть — ставьте его обычным способом.

## 2. xlsx2bpmn: таблица → диаграмма

```bash
xlsx2bpmn --template Процесс.xlsx     # получить шаблон с примером
# ... заполнить таблицу ...
xlsx2bpmn Процесс.xlsx                # рядом появится Процесс.bpmn
```

**Что принимает.** Таблицу в двух видах, различая их по содержимому файла,
а не по расширению:

- **xlsx** — книга по шаблону из `--template`;
- **текст** — колонки разделены вертикальной чертой `|`, кодировка UTF-8
  или CP1251.

Другие разделители не принимаются. Пробелы вокруг черт срезаются. При лишней
или недостающей черте утилита называет номер строки.

### Субпроцессы отдельными листами

В книге **первый лист — весь процесс, каждый следующий — содержимое одного
субпроцесса**. Имя листа должно совпадать с `id` строки субпроцесса
в главном листе:

```
лист «Process»    ... sub_check | Проверка поставщика | subProcess | ...
лист «sub_check»  ... шаги, из которых состоит эта проверка
```

Колонку `parent_id` при этом заполнять не нужно — она проставляется по имени
листа. Вложенность любой глубины: субпроцесс внутри субпроцесса — просто ещё
один лист с его id.

Листы без колонок `id`, `type`, `pool` пропускаются, поэтому лист «Справка»
из шаблона не мешает. Если имя листа не совпало ни с одним id — придёт ошибка
с номером листа, а не молчаливая потеря.

Всё это — сахар над колонкой `parent_id`: одностраничная таблица с ней
работает по-прежнему.

**Что отдаёт.** Файл `.bpmn` с расставленными координатами — открывается
в любом BPMN-редакторе: перетащите на demo.bpmn.io или откройте в Camunda
Desktop Modeler. Оба работают локально.

**Команды:**

```bash
xlsx2bpmn --template Процесс.xlsx             # создать шаблон таблицы
xlsx2bpmn Процесс.xlsx                        # → Процесс.bpmn
xlsx2bpmn Процесс.txt                         # текстовая таблица тоже годится
xlsx2bpmn Процесс.xlsx -o схема.bpmn          # своё имя выходного файла
xlsx2bpmn Процесс.xlsx -o схема.png           # ТОЛЬКО картинка, без .bpmn
xlsx2bpmn Процесс.xlsx -o схема.svg           # то же вектором
xlsx2bpmn Процесс.xlsx --levels                        # какие есть уровни
xlsx2bpmn Процесс.xlsx --all-levels                    # папка: каждому уровню три файла
xlsx2bpmn Процесс.xlsx -o внутри.png --level sub_check # картинка субпроцесса
xlsx2bpmn Процесс.xlsx --png --svg            # .bpmn и обе картинки рядом
xlsx2bpmn *.xlsx                              # пачкой, каждому свой .bpmn
xlsx2bpmn Процесс.xlsx --sheet Лист1          # таблица на другом листе
xlsx2bpmn Процесс.xlsx --target camunda8 --executable
xlsx2bpmn Процесс.xlsx --strict               # предупреждения тоже блокируют
xlsx2bpmn Процесс.xlsx --no-layout            # без координат, только структура
xlsx2bpmn Процесс.xlsx --report ошибки.txt    # отчёт в файл
xlsx2bpmn Процесс.xlsx -q                     # молча
```

**Ключи:**

| Ключ | Что делает |
|---|---|
| `--template PATH` | создать пустой шаблон и выйти |
| `--setup-layout` | проверить раскладчик; обычно не нужно — он уже внутри |
| `-o, --output` | имя результата; расширение `.png` или `.svg` даёт только картинку |
| `--png` / `--svg` | нарисовать картинку рядом с `.bpmn` |
| `--level ID` | работать с содержимым субпроцесса, а не со всем процессом |
| `--levels` | показать уровни схемы и выйти |
| `--all-levels` | сложить все уровни в папку: каждому таблица, `.bpmn` и картинка |
| `--sheet` | имя главного листа, по умолчанию `Process` |
| `--target` | `plain` (по умолчанию) или `camunda8` |
| `--executable` | пометить процесс исполняемым |
| `--no-layout` | не расставлять координаты |
| `--strict` | предупреждения блокируют генерацию наравне с ошибками |
| `--report PATH` | записать ошибки и предупреждения в файл |
| `-q, --quiet` | без подробного вывода |
| `--version` | показать версию |

## 3. bpmn2xlsx: диаграмма → таблица

```bash
bpmn2xlsx Схема.bpmn                  # рядом появится Схема.xlsx
```

**Что принимает.** Любой файл BPMN 2.0 — от Camunda Modeler, bpmn.io, чужой
системы. Координаты в нём не обязательны.

**Что отдаёт.** Таблицу в двух видах:

- **xlsx** (по умолчанию) — все 15 колонок поверх вложенного шаблона, так что
  выпадающие списки и лист «Справка» остаются на месте;
- **текст** (`--txt`) — только заполненные колонки, удобно для git и для
  языковой модели.

Субпроцессы раскладываются **по отдельным листам**, названным их id, — в том
самом виде, в котором книга читается обратно. Круг замыкается без правок.

### Обращение к отдельному субпроцессу

```bash
bpmn2xlsx Схема.bpmn --levels                        # что внутри
bpmn2xlsx Схема.bpmn --level sub_check --txt         # таблица только его
bpmn2xlsx Схема.bpmn --level sub_check -o он.png     # картинка только его
```

`--levels` печатает сам процесс и каждый субпроцесс с числом элементов:

```
уровень               название                          элементов
(весь процесс)                                          6
sub_check             Проверка поставщика               4
```

### Все уровни сразу — папка с тремя файлами на каждый

```bash
xlsx2bpmn Закупка.xlsx --all-levels     # от таблицы
bpmn2xlsx Закупка.bpmn --all-levels     # от диаграммы — то же самое
```

Рядом появится папка `Закупка/`, а в ней — по три файла на каждый уровень,
все на одном уровне вложенности:

```
Закупка/
  01-Закупка.xlsx              весь процесс: книга со всеми листами
  01-Закупка.bpmn              весь процесс: схема со всеми полотнами
  01-Закупка.png
  02-Проверка-поставщика.xlsx  только этот субпроцесс
  02-Проверка-поставщика.bpmn
  02-Проверка-поставщика.png
  03-Экспертиза.xlsx           субпроцесс внутри субпроцесса
  03-Экспертиза.bpmn
  03-Экспертиза.png
```

Номер задаёт порядок: первым идёт весь процесс, дальше субпроцессы сверху вниз.
Имя — название уровня, а не его id, так что папку можно отдавать как есть.

**Каждая тройка самодостаточна.** Файл субпроцесса — не вырезка, а нормальная
схема: `parent_id` очищен, документы уровня едут вместе с ним, ссылки наружу
убраны. Такой `.bpmn` открывается в Modeler, такую `.xlsx` можно править
и скормить обратно `xlsx2bpmn`. Внутри тройки всё сходится: таблица собирает
именно этот `.bpmn`, а он рисует именно эту картинку.

Ключ `--svg` добавит к каждому уровню ещё и вектор. Папку задаёт `-o`:

```bash
xlsx2bpmn Закупка.xlsx --all-levels -o /выгрузка/Закупка --svg
```

**Команды:**

```bash
bpmn2xlsx Схема.bpmn                          # → Схема.xlsx
bpmn2xlsx Схема.bpmn --txt                    # текстовая таблица вместо книги
bpmn2xlsx Схема.bpmn -o таблица.txt           # формат берётся из расширения
bpmn2xlsx Схема.bpmn -o схема.png             # ТОЛЬКО картинка, без таблицы
bpmn2xlsx Схема.bpmn -o схема.svg             # то же вектором
bpmn2xlsx Схема.bpmn --png --svg              # таблица и обе картинки рядом
bpmn2xlsx *.bpmn                              # пачкой
bpmn2xlsx Схема.bpmn --levels                 # какие есть уровни
bpmn2xlsx Схема.bpmn --all-levels             # папка: каждому уровню три файла
bpmn2xlsx Схема.bpmn --level sub_check --txt  # таблица одного субпроцесса
bpmn2xlsx Схема.bpmn --report потери.txt      # отчёт о потерях в файл
bpmn2xlsx Схема.bpmn -q                       # молча
xlsx2bpmn Схема.bpmn --to-table               # то же самое другим именем
```

**Ключи:**

| Ключ | Что делает |
|---|---|
| `-o, --output` | имя результата; расширение решает формат: `.xlsx`, `.txt`, `.png`, `.svg` |
| `--txt` | текстовая таблица вместо книги |
| `--png` / `--svg` | нарисовать картинку рядом с таблицей |
| `--level ID` | взять только содержимое субпроцесса — и в таблицу, и в картинку |
| `--levels` | показать уровни схемы и выйти |
| `--all-levels` | сложить все уровни в папку: каждому таблица, `.bpmn` и картинка |
| `--report PATH` | записать список потерь в файл |
| `-q, --quiet` | без подробного вывода |
| `--version` | показать версию |

Если у присланной диаграммы нет координат, картинка всё равно получится:
схема сначала раскладывается своим раскладчиком.

### Что не переживает разбор

Таблица — проекция BPMN, и проекция с потерями. Всё потерянное утилита
называет вслух, молча не выбрасывает ничего:

| Что | Судьба |
|---|---|
| координаты | теряются, при обратной сборке раскладчик расставит заново |
| **пустые** пулы — нарисована рамка, а внутри ничего | в таблице не представимы, см. ниже |
| текстовые аннотации, связи, группы | в модели таблицы их нет |
| расширения движков (`zeebe:`, `camunda:`) | не переносятся |
| типы вне списка (`transaction`, `complexGateway`) | пропускаются |

Ссылки на всё пропущенное вычищаются, поэтому полученная таблица всегда
собирается обратно. Символ `|` в названиях заменяется на `/`, служебные
скобки в подписях потоков — на круглые; про каждую замену приходит
предупреждение.

**Обычные пулы разбор переживают полностью** — они становятся колонкой `pool`,
дорожки внутри них колонкой `lane`. Не переживает только пустой пул: в BPMN
это рамка с названием и без содержимого, ею рисуют внешнюю сторону, чьё
устройство не описывают. В таблице пул существует не сам по себе, а как
значение в строках, поэтому пул без единой строки исчезает — выразить его
нечем. Утилита о таком предупреждает поимённо.

Главное следствие для работы: **ручная компоновка не переживает оборот.**
Разложили схему в Modeler, прогнали через таблицу — координаты будут
посчитаны заново.

## 4. Коды возврата

Обе команды возвращают одно и то же: `0` — успех, `1` — ошибки в таблице,
`2` — файл не прочитан, `3` — не удалось нарисовать. Удобно для скриптов:

```bash
xlsx2bpmn Процесс.xlsx -q || echo "не собралось"
```

## 5. Как заполнять таблицу

Одна строка — один элемент. Связи пишутся у источника в колонке `next`.

| Что нужно | Как записать |
|---|---|
| Простой переход | `next: t_check` |
| Развилка AND | `next: t_invoice; t_pack` |
| Ветка с условием | `next: t_pay [Да] {amount > 1000}` |
| Ветка по умолчанию | `next: *t_reject [Нет]` |
| Сообщение в другой пул | `message_to: c_pay` |
| Задача создаёт документ | `data_out: doc_req` |
| Задача читает документ | `data_in: doc_req` |
| Сам документ | отдельная строка, `type: dataObject` |

Обязательные колонки — `id`, `type`, `pool`. Дорожки создаются
автоматически по названию в колонке `lane`. Полное описание всех колонок —
на листе «Справка» внутри шаблона.

### Документы

Документ объявляется отдельной строкой с `type = dataObject` и живёт внутри
одного пула. Движение читается по цепочке: одна задача его создаёт (`data_out`),
следующая читает (`data_in`).

Ограничение самого BPMN: передать документ из пула в пул ассоциацией нельзя —
между пулами идёт поток сообщений, а документ объявляется в каждом пуле свой.
Валидатор это ловит.

## 6. Генерация таблицы языковой моделью

В `xlsx2bpmn/prompt.md` лежит промпт для локальных моделей: закрытый список
типов, явный формат, два проверенных примера, чеклист самопроверки. Подставьте
свои пути вместо `{{INPUT_MD}}` и `{{OUTPUT_TXT}}`, отдайте модели, полученную
таблицу скормите утилите.

Готовая обвязка для Open WebUI — в `owui/`: там модель вызывается сама, ответ
проверяется, при ошибках возвращается ей на исправление. Описание процесса
можно не набирать, а приложить файлом — docx, pdf, pptx, xlsx, html читаются
через `markitdown`. Установка — `owui/УСТАНОВКА.md`.

Чтение документов включается дополнением `[docs]` при установке (раздел 1)
и доступно как обычная функция:

```python
from xlsx2bpmn import read_document
text = read_document(open("регламент.docx", "rb").read(), "регламент.docx")
```

Валидатор ловит битые ссылки и структурные ошибки, но не заметит, если модель
неверно поняла смысл процесса — результат проверяйте.

## 7. Раскладка координат

Раскладчиков два, и выбирать между ними не нужно: по умолчанию
(`--layout auto`) каждый процесс получает тот, который справится.

**Правило простое — по дорожкам.**

**Есть дорожки → встроенный.** Он единственный их понимает: каждой роли своя
полоса, элемент не уезжает в чужую. bpmn-auto-layout про дорожки не знает и
выстраивает всё одной строкой — «Зарезервировать товар» оказывается в полосе
«Приём», а это уже не косметика, а искажение смысла: читающий отнесёт задачу
не к той роли.

**Нет дорожек → bpmn-auto-layout.** Процесс он ведёт заметно ровнее: главная
цепочка идёт одной прямой, ветки уходят строкой ниже.

Правило работает на каждый пул отдельно, поэтому в схеме, где у одного пула
дорожки есть, а у другого нет, каждый разложат по-своему. В выводе видно, что
получилось:

```
OK -> схема.bpmn  ...  раскладка: bpmn-auto-layout + встроенный
```

**Ставить ничего не нужно.** bpmn-auto-layout зашит в пакет одним файлом
(`layout-node/bundle.mjs`, 170 КБ) вместе со всеми зависимостями и работает
сразу после `pip install`, без `npm install` и без сети. Всё внутри —
под лицензией MIT, тексты лицензий в `layout-node/THIRD-PARTY.md`.

Единственное, что для него нужно, — **Node.js 20 или новее** в системе.
Если его нет, схемы без дорожек разложит встроенный, а утилита один раз
скажет, чего не хватает:

```
раскладка: встроенный  (схему без дорожек можно вести ровнее,
                        но для этого нужен Node.js 20+: https://nodejs.org)
```

Взять один раскладчик принудительно: `--layout native` или `--layout node`.

### Как ведутся стрелки

Маршруты выбираются заново, поверх любого раскладчика. Для каждой стрелки
собираются варианты — тот, что провёл раскладчик, простые обходы (прямая,
угол, скобка на разных сторонах плашек) и, если простых не хватило, путь
поиском по сетке из границ самих фигур. Варианты меряются одной меркой:

| Что меряем | Цена |
|---|---|
| длина | 1 за пиксель |
| излом | 60 |
| пересечение с чужой стрелкой | 250 |
| участок по чужой линии | 2 за пиксель |
| выход не с той стороны, куда стрелка идёт | 40 |
| причал, уже занятый другой стрелкой | 600 |
| действующему маршруту | скидка 60 |

Берётся лучший. Скидка действующему нужна, чтобы удачную линию не дёргать
без выигрыша. Проходов два: на втором стрелка выбирает маршрут, уже видя
улучшенных соседей, — так пересечений заметно меньше.

**Из одной точки две стрелки не выходят.** Две линии, вышедшие из одного
места, читаются как одна: у развилки не видно, где какой ответ. Поэтому
причалы разводятся — сначала по разным сторонам фигуры (у ромба их четыре),
а если сторону приходится делить, то со сдвигом вдоль неё. Правило действует
и на входе: три стрелки в одно событие войдут в три разные точки.

**Сквозь плашку не проходит ни одна.** Вариант, задевающий чужую фигуру,
выбывает сразу, и это же правило запрещено нарушать поиску. Если схема
настолько плотная, что обходного пути нет вовсе, стрелка остаётся как была
и в вывод приходит предупреждение с их числом — молча кривая линия не
остаётся. `selftest.py` проверяет правило на каждой из своих схем.

Что это даёт (до раскладки маршрутов → после):

| | шаблон | 16 шагов | схема с двумя развилками |
|---|---|---|---|
| сквозь плашки | 6 → **0** | 8 → **0** | 1 → **0** |
| стрелок из одной точки | 7 → **0** | 4 → **0** | 3 → **0** |
| пересечений | 16 → **14** | 32 → **20** | 0 → **0** |
| внахлёст, px | 340 → **0** | 4310 → **180** | 300 → **0** |
| изломов | 22 → 29 | 40 → 45 | 6 → **4** |

Изломов местами становится больше — это плата за обход: линия, шедшая сквозь
задачу, теперь её огибает. `selftest.py` проверяет оба правила на четырёх
схемах, включая схему с двумя развилками подряд.

**Документы расставляет наш код в обоих случаях.** bpmn-auto-layout
складывает их столбиком в стороне от схемы; мы это отбрасываем и ставим
каждый документ вплотную к задаче, которая его создаёт.

Картинку можно получить сразу: ключи `--png` и `--svg` рисуют схему рядом
с результатом, а `-o схема.png` — вместо него.

### Своя раскладка

`apply_layout` вторым аргументом принимает любую функцию `str -> str`:
на вход XML с одним процессом, на выход он же с добавленным `BPMNDiagram`.
Ваша тулза расстановки координат подключается одной строкой.

## 8. Использование как библиотеки

```python
from xlsx2bpmn import convert, apply_layout, layout_process

result = convert(open("process.xlsx", "rb").read(), target="plain")

if not result.ok:
    for issue in result.issues:
        print(issue)                    # [строка 14] ERROR ...
else:
    xml, warnings = apply_layout(result.xml, layout_process)
    open("process.bpmn", "w", encoding="utf-8").write(xml)
```

`convert(data: bytes, *, sheet=None, strict=False, executable=False,
target="plain") -> Result`

`Result` содержит `ok`, `xml`, `issues` (у каждого — `level`, `row`, `message`)
и `stats`. Функция ничего не читает с диска и не пишет: даёте байты,
получаете результат.

Обратный ход устроен зеркально:

```python
from xlsx2bpmn import to_table, to_workbook

result = to_table(open("process.bpmn", encoding="utf-8").read())

print(result.table)                     # текст с разделителем |
for issue in result.warnings:
    print(issue)                        # что не уложилось в таблицу
```

`to_table(xml: str | bytes, *, full=False) -> TableResult`

`TableResult` содержит `table` (готовый текст), `rows` и `columns` (те же
данные структурой), `issues` и `stats`. При `full=True` выводятся все 15
колонок, иначе только заполненные. `to_workbook(result, template_bytes)`
раскладывает строки по шаблону и возвращает байты `.xlsx`.

Обе функции чистые — ни диска, ни сети, — поэтому пакет одинаково удобно
звать из скрипта, из веб-обвязки или из функции Open WebUI.

## 9. Если не сконвертировалось

Ошибки блокируют результат, предупреждения — нет. У каждой указан номер строки
таблицы. Самые частые:

| Сообщение | Причина |
|---|---|
| `next ссылается на несуществующий id` | опечатка в идентификаторе |
| `условия заданы у N, поток по умолчанию не указан` | у эксклюзивного шлюза не хватает условия или `*` |
| `документ объявлен в другом пуле` | документ живёт внутри одного пула |
| `в пуле нет startEvent` | у каждого пула должны быть старт и конец |
| `поток пересекает пулы` | между пулами используется `message_to`, а не `next` |

## 10. Ограничения

Встроенный раскладчик не минимизирует пересечения стрелок: на процессах с
множеством обратных связей схема будет читаемой, но не оптимальной.

Субпроцессы рисуются свёрнутыми, но их содержимое не теряется: на каждый
субпроцесс строится отдельное полотно, и редактор показывает вложенные шаги
при раскрытии. Вложенность любой глубины переживает разбор в таблицу через
колонку `parent_id`.

Режим `camunda8` подставляет `zeebe:taskDefinition` с типом джоба, выведенным
из `id` задачи — это заглушка, проверьте перед развёртыванием. Корреляцию
сообщений таблица не описывает, её дописывают в Modeler.

## Что менялось

Номер версии растёт при каждом изменении поведения. Если ваш
`xlsx2bpmn --version` отстаёт — обновитесь по разделу 1.

**1.13.0**
- раскладчик больше не надо выбирать и не надо ставить. bpmn-auto-layout
  зашит в пакет одним файлом и работает сразу после `pip install`; нужен
  только Node.js в системе
- выбор идёт по схеме, отдельно для каждого пула: есть дорожки — встроенный,
  он единственный их соблюдает; нет дорожек — bpmn-auto-layout, он ведёт
  процесс ровнее. Раньше `auto` брал bpmn-auto-layout всегда, когда тот был
  установлен, и на схеме с дорожками роли переставали совпадать с полосами
- в выводе видно, чем разложено на самом деле

**1.12.0**
- две стрелки больше не выходят из одной точки. Это было заметнее всего на
  развилках: оба ответа выходили из одной вершины ромба, и какой из них
  какой — понять было нельзя. Теперь причалы разводятся по сторонам, а если
  сторону приходится делить — со сдвигом вдоль неё
- то же на входе: несколько стрелок в одно событие входят в разные точки
- правило проверяется в `selftest.py` и держится на всех схемах, вплоть
  до синтетической на 150 шагов

**1.11.0**
- маршруты выбираются заново для каждой стрелки, а не только для проткнутых:
  из нескольких вариантов берётся лучший по длине, изломам, пересечениям
  и участкам внахлёст. Линий, идущих друг по другу, стало втрое-сорокакратно
  меньше
- `--setup-layout` ставит bpmn-auto-layout одной командой. Раньше его папка
  оставалась в клоне и после `pip install` не находилась — то есть схемы почти
  наверняка раскладывались запасным раскладчиком, который ведёт линию хуже.
  Теперь она едет вместе с пакетом, а утилита сама напоминает о ней в выводе
- `pip` больше не ставит версию 1.8.0 при любом номере в коде: в pyproject
  версия застряла и не поднималась с тех пор

**1.10.0**
- стрелка больше не проходит сквозь плашку — ни при каких условиях. Готовый
  план проверяется, и каждая проткнутая стрелка перекладывается в обход
  (поиск по сетке со штрафом за поворот), а стрелки, никого не задевающие,
  остаются такими, какими их провёл раскладчик
- параллельные стрелки не сливаются: занятая линия стоит дороже свободной
- линия к документу больше не прошивает свою же задачу: причал берётся с той
  стороны, где документ действительно стоит
- содержимое субпроцесса больше не валится поверх основного потока: под
  bpmn-auto-layout, который вложенности не знает, полотна субпроцессов
  строятся сами
- документ, которым пользуется задача внутри субпроцесса, наконец рисуется —
